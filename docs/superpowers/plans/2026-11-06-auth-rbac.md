# Authentication and Role-Based Access Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace simulated browser authentication with revocable MySQL-backed sessions and enforce identity, ownership, and roles on protected pages and APIs.

**Architecture:** Keep Next.js App Router and `mysql2`. Persist only a SHA-256 digest of a random opaque session token; send the token in an HttpOnly, SameSite=Lax cookie. Resolve the current account and current role in server code for every protected operation; use Proxy only for navigation redirects, never as the authorization boundary.

**Tech Stack:** Next.js 16.4.5, React 19.3, TypeScript, MySQL/mysql2, bcryptjs, Vitest.

## Global Constraints

- Conserver MySQL et les accès SQL actuels avec `mysql2`; ne pas introduire de changement d’ORM.
- À chaque requête protégée, retrouver une session non expirée et charger le compte et son rôle actuels depuis MySQL. Ne pas prendre le rôle depuis une donnée contrôlée par le navigateur.
- Une inscription publique crée toujours un `apprenant`. L’attribution des rôles privilégiés est réservée à une action serveur protégée par le rôle `admin`.
- Le cookie est `HttpOnly`, `SameSite=Lax`, `Path=/`, avec une durée de sept jours et l’attribut `Secure` en production.
- Refuser l’accès en cas de panne de base ou de configuration requise ; ne pas transformer une erreur en session valide.
- Les opérations sur les données personnelles utilisent l’identifiant du compte connecté et ignorent tout `userId` fourni par le client.
- Chaque route API protégée applique sa propre autorisation ; le middleware/proxy seul n’est jamais une barrière d’autorisation.
- MySQL est l’unique source de vérité pour comptes, sessions, abonnements, progression, évaluations, projets et certificats ; aucune bascule silencieuse vers un fichier ou la mémoire.
- L’import initial de `src/data/local-database.json` conserve les identifiants de connexion hachés et les données associées, ne remplace jamais un compte MySQL existant, et ne supprime ni ne modifie le fichier source.
- La configuration DB du projet est `DATABASE_URL` ; ne jamais remplacer cette configuration par des variables `DB_HOST`/`DB_USER` ou par des valeurs de repli.
- Les mots de passe intégrés `demo123` et `admin123` ne doivent jamais être importés comme mots de passe valides ; demander des remplacements masqués dans le terminal et ne jamais les afficher.
- La progression auparavant conservée dans le cache du navigateur doit être migrée vers MySQL par l’utilisateur connecté ; ne supprimer l’ancienne clé locale qu’après confirmation serveur de tous les éléments.

```ts
export async function requireUser(): Promise<AuthenticatedUser> {
  const token = (await cookies()).get(SESSION_COOKIE)?.value;
  const user = await getUserForSession(token);
  if (!user) throw new AuthenticationError(401, "Authentication required");
  return user;
}

export async function requireRole(
  roles: readonly UserRole[],
): Promise<AuthenticatedUser> {
  const user = await requireUser();
  if (!roles.includes(user.role)) {
    throw new AuthenticationError(403, "Insufficient role");
  }
  return user;
}
```
